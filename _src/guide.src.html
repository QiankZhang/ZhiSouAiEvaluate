00 — Before you start

开始之前

智搜评估系统用来衡量「智搜」策略调整后的效果：把一批真实查询与智搜的回答喂给 AI 裁判员模型按既定标准打分，再由人工复核兜底，最后自动汇总成评估报告。

三样东西凑齐，才能跑一次评估

两种评估机制（贯穿全系统）

系统底层只有两种打分机制，它决定数据集的必需列、基准的配置项、报告的呈现方式。 机制的显示名称可以自定义（如把「多维度」改叫「语义相似度评估」），但底层仍是这两种之一。

多维度　MULTI_DIM

按若干维度加权打分，每维 1–5 分。

  • 必需列：query、content
  • 基准里配「维度 + 权重」，权重合计需 = 100%
  • 报告给出各维度均值、低分占比、总分分布

GSB 对比　GSB

实验对象 vs 基线对象，逐条判 Good / Same / Bad。

  • 必需列：query、content、baseline
  • 基准里配「判定规则 + 裁决维度」
  • 报告给出 G∶S∶B、胜率、净胜率 =（G−B）/（G+S+B）

导航与角色

左侧边栏进入四大工作台：数据概览 评估中心（即评估任务管理） 数据集 评估基准。 「数据源连接」标注 待开发，暂不可用。

协同分工

人工定标准——由你设计数据集与评估基准；AI 做执行——裁判员模型逐条打分；人工兜置信——你在任务详情里逐条复核，通过或调整后报告才最终定稿。

01 — Datasets

数据集管理

数据集是一批待评样本的集合。进入侧边栏「数据集」查看全部数据集， 支持按名称 / ID 搜索，按来源（文件上传 / 示例生成 / 数据库直连）、 创建人、创建时间筛选。

创建数据集

点击右上角「创建数据集」，在弹窗中填写并上传文件。

  1. 填写数据集名称（必填，≤ 50 字）与数据集描述（选填，≤ 200 字）。

  2. 选择评估方式。它决定必需列——多维度机制需 query / content；GSB 机制额外需 baseline。

    下拉底部的「+ 新增评估方式…」可自定义一个显示名称，并指定它属于「多维度机制」还是「GSB 机制」。

  3. 点「下载标准模板」拿到对应机制的 CSV 表头，或点「查看数据集样例」直接在弹窗里预览字段格式。

  4. 把整理好的文件拖入上传区，或点击选择。支持 CSV / JSON / JSONL / XLSX，单文件 ≤ 50 MB。

  5. 点「保存」。若某些行缺少必需列，弹窗会按「第 N 行：原因」逐条列出错误，修正后重新上传即可。

字段说明约束
数据集名称 必填列表与选择器中显示的名称≤ 50 字
数据集描述用途与范围说明≤ 200 字
评估方式 必填决定必需列与后续可匹配的基准多维度机制 / GSB 机制
数据文件 必填样本内容CSV / JSON / JSONL / XLSX，≤ 50 MB
query用户查询两种机制都必需
content智搜回答（实验对象）两种机制都必需
baseline基线回答（对照对象）仅 GSB 机制必需

查看与维护

点数据集名称进入详情页：上方是基本信息（条数、字数、创建人、时间）与 被引用任务列表，下方是样本预览（仅展示前若干条，GSB 会多出「基线内容」列）。 列表页每行操作区可下载原始文件或删除。

删除限制

只要数据集正被任意评估任务引用，删除按钮即不可用。需先删除或改绑相关任务，才能删除该数据集。

02 — Benchmarks

评估基准管理

评估基准 = 一套可复用的打分标准。进入侧边栏「评估基准」， 可按评估类型（提示词类型 / 技能 Skill）、评估方式（多维度 / GSB）、创建人筛选。 每个基准带版本号与状态（已验证 / 未验证），以及被任务引用的使用次数。

创建评估基准（两步向导）

第一步 · 基础信息

  1. 填写基准名称（必填，≤ 50 字）与基准描述（选填，≤ 200 字）。

  2. 选择评估类型：

    提示词类型 用提示词编辑器 + 变量面板表达标准；技能 Skill 使用符合 Anthropic Agent Skills 规范的技能包。

  3. 选择评估方式（多维度机制 / GSB 机制，同样支持「+ 新增评估方式」自定义显示名）。点「下一步」。

第二步 · 指令配置（内容随「评估类型 × 评估方式」变化）

  1. 提示词类型：在提示词编辑框写评测指令，可从变量面板插入 {query} {待评内容} {维度} {评分标准}（GSB 另有 {基线内容}）。 维度、权重、评分标准、判定规则都直接写在提示词里。下方标准输出格式展示裁判员模型应返回的 JSON 结构。

  2. 技能 Skill：选技能来源——「内置技能」（multi-dimension-evaluation / gsb-evaluation，随平台维护）， 或「上传技能包」（.zip 根目录含 SKILL.md，或单个 SKILL.md，≤ 10 MB）。上传后系统解析并展示技能名称、版本、许可证与说明。

  3. 按需勾选「输出结果附带置信度字段」。

  4. 多维度机制：在维度与权重区增删维度、填写权重，底部实时显示合计，必须等于 100%才能保存。

    GSB 机制：填写判定规则（≤ 200 字）与裁决维度（如 overall / relevance）；数据集里的 baseline 即基线对象。

  5. 点「保存」。

配置项提示词类型技能 Skill
标准表达提示词编辑框 + 变量面板内置技能，或上传 SKILL.md / .zip
多维度机制维度与权重区，权重合计 = 100%
GSB 机制判定规则 + 裁决维度；baseline 作基线
置信度勾选「输出结果附带置信度字段」

查看与维护

点基准名称进入详情页，按配置类型分别展示维度与权重 / GSB 判定规则 / 技能 Skill 详情 / 提示词全文，以及被引用任务。 行内 / 详情页均可编辑、复制（生成新基准便于微调）、删除。

删除限制

使用次数 > 0（正被任务引用）的基准无法删除。可先复制一份作为新版本迭代，旧版本留给历史任务。

03 — Evaluation tasks

评估任务管理

侧边栏「评估中心」即评估任务管理。列表展示每个任务的 状态、评估方式、所用基准、样本量与进度，可按任务名 / ID 搜索， 按状态、评估方式、任务类型、裁判员模型筛选。

状态含义可用操作
未开始已创建、尚未执行执行评测 · 编辑 · 复制 · 删除
执行中裁判员模型正在逐条打分停止
已完成打分完成，待 / 已复核查看报告 · 复制任务 · 下载测试集 · 删除
已停止执行中被手动停止执行评测（继续）· 编辑 · 复制 · 删除
执行失败执行异常终止重试 · 编辑 · 查看失败原因

第 1 步 · 创建任务

  1. 点右上角「创建评测任务」。填写任务名称（必填，≤ 50 字）、任务描述（选填，≤ 50 字）。

  2. 填任务类型（自由文本，输入过的会进联想；默认建议「通用评估」「博文分析」）——仅用于数据概览的类型统计。

  3. 选评估基准（必填）。评估方式由基准隐式决定，并据此过滤下方可选数据集。

  4. 选评测数据（必填，只列出与基准同机制的数据集）。也可点「创建新数据集」就地新建。

  5. 选AI 裁判员模型（必填）。默认 deepseek-v4-flash（DeepSeek Flash，真实调用）。

  6. 弹窗底部给出预估：字数、token、耗时、成本。确认后点「创建任务」。

第 2 步 · 执行评测

在列表或任务详情点「执行评测」，任务转入执行中， 详情页显示实时进度条（已完成 / 总样本）。需要时可「停止」；执行失败时点「重试」， 并在详情页顶部查看失败原因。

进度四段

任务详情顶部的步骤条对应：数据准备 → AI评测 → 人工复核 → 报告。统计行会显示样本量、预估字数、预估 / 实际成本、预估耗时、评测引擎（真实调用 / 模拟，或「部分降级」）与复核进度。

第 3 步 · 人工复核

打分完成后，在任务详情的「评测结果」表逐条复核。每行给出样本 Query、评分（多维度总分及各维分；GSB 为 Good/Same/Bad 及双方总分）与理由。

  1. 认可 AI 判分——点该行「通过」。

  2. 需要修正——点「调整」：多维度可改各维 1–5 分（总分自动按权重重算）；GSB 可改判定结果；并填写复核说明。保存后该行标记已调整。

  3. 批量处理——点表头「全部通过（N）」一次通过所有待复核行。

  4. 所有行复核完毕后，复核状态转为已复核，系统自动跳转到评估报告页。

第 4 步 · 阅读评估报告

报告页按固定五段式组织，与可导出的 Markdown 结构一一对应：

章节多维度GSB
一　整体结论最弱 / 最强维度、全链路判断整体强弱于基线，G∶S∶B 速览
二 / 三　专项分析三　分维度问题分析：各维均值、低分占比、总分分布二　GSB 专项评估：Good/Same/Bad、胜率、净胜率
四　典型错误 case按错误类型聚合 + 2~3 个典型 case 详评（原始 Query、问题定位、原文问题片段）
五　改进建议对应共性短板的可落地建议

页面右上角可复制 Markdown、下载 Markdown、下载 Excel（原始打分表）。 报告下方还有逐样本明细表与可展开的 Markdown 源码。 若人工复核尚未完成，报告顶部会提示「初步统计，复核结果确认后同步更新」。

复用与追溯

已完成任务可「复制任务」快速发起回归；「下载测试集 / 评估测试集」导出逐样本打分明细（CSV）。任务详情头部始终显示所用基准、数据集、裁判员模型与引擎，便于追溯。

04 — Overview

评估数据概览

侧边栏「数据概览」是全局监控视图，进入系统的默认落地页。 右上角切换时间范围：今日 近7天 近30天 自定义（选自定义后需指定起止日期，指标才会加载）。

区块内容
核心指标卡所选区间的评估量（条）、已完成任务（个）、执行中任务（个）、已评测样本（条）
评估量趋势按样本条数的每日柱状图，标注区间起止日期
任务类型分布按任务创建时填写的「任务类型」聚合占比（如通用评估 / 博文分析）
让统计更准

概览的「任务类型分布」直接取自创建任务时填写的任务类型字段。团队约定统一的类型命名（并善用输入联想），分布图才有参考价值。

本指南依据当前线上界面整理，涉及页面：数据概览、评估中心（任务）、数据集、评估基准。界面文案与按钮以系统实际显示为准。
